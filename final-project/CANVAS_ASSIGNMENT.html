🔄 Git Workflow for the Final Project

Use the same branch workflow as prior weeks:

Step 1: Create a Branch

# Make sure you're on main and it's up to date
git checkout main
git pull origin main

# Create a new branch for your final project
git checkout -b assignment/final-project

Step 2: Scaffold Your Project

# Navigate to the final-project folder
cd final-project

# Create a new console app with your chosen name (replace YourAppName)
dotnet new console -n YourAppName

# Open the new folder
cd YourAppName

Step 3: Build and Test Your App

# Run your app at any time
dotnet run

# Format your code before committing
dotnet format

Step 4: Commit Your Work

# Stage everything in the final-project folder
git add final-project/

# Commit with a clear message
git commit -m "Final Project: [Your App Name]"

Step 5: Push to GitHub

# Push your branch
git push -u origin assignment/final-project

Step 6: Create Pull Request

  1. Go to your repository on GitHub
  2. Click "Compare & pull request" button
  3. Set base branch to main
  4. Title: Final Project: [Your App Name]
  5. Add a short description of what your app does
  6. Click "Create pull request"

Step 7: Submit PR URL on Canvas

Copy the pull request URL and submit it in the Canvas assignment text box. If you recorded a video walkthrough for bonus points, include the video link in the same text box.

📝 Assignment Requirements

You choose the app idea. It can be anything that interests you — a personal budget tracker, a recipe manager, a contact book, a simple quiz game, a workout log — as long as it demonstrates the required concepts listed below. Keep it simple and focused; a small app done well is better than a large one left half-finished.

Part 1: Plan First — DATA_MODEL.md (10 points)

Before writing any code, fill out final-project/DATA_MODEL.md with:

  • A 1–2 sentence scenario describing what your app does
  • At least 5 named inputs with their data types
  • Any calculated or derived values
  • What the user will see as output
  • One edge case your app needs to handle

Part 2: Build Your App — Required Concepts (40 points)

Your app must demonstrate all 8 of the following concepts:

# Required Concept Introduced
1 Variables using appropriate data types (string, int, double, bool) Week 3
2 If/else decisions (at least one conditional branch) Week 4
3 At least one loop (while, do-while, or for) Week 5
4 Formatted string output (labels, alignment, or headers) Week 6
5 An array or List<T> storing multiple items Week 7
6 At least one custom class in its own .cs file Week 8
7 At least two named methods beyond Main Week 9
8 Read from or write to a file (CSV or plain text) Week 10

Part 3: Code Quality (5 points)

  • Include the course file header in every .cs file
  • Run dotnet format before committing
  • Use clear, readable variable and method names

Part 4: Reflection — README.md (10 points)

Fill out the reflection section at the bottom of final-project/README.md:

  • What your app does (1–3 sentences)
  • Why you chose this idea
  • Which required concepts you used and where
  • What was most challenging and how you solved it
  • Total time spent and a rough breakdown

🎬 Bonus: Video Walkthrough (+25 points)

Record a 5–10 minute video that includes:

  1. App demo — Run your app and walk through what it does (2–4 min)
  2. Code tour — Open your code and briefly explain where each required concept appears (3–6 min)

Upload to YouTube (unlisted), Loom, or Google Drive (shareable link) and paste the URL in the Canvas submission text box alongside your PR link.

Tip: You don't need to be polished — just clear and genuine. Screen recording with your voice is all you need.

💡 Tips for Success

  • Start with DATA_MODEL.md — planning before coding saves you from rewriting everything halfway through
  • Keep it small — a Contact Book with 4 menu options is better than a half-finished e-commerce system
  • Build one piece at a time — get dotnet run working early, then add features one by one
  • Commit often — small commits are easier to undo if something breaks
  • Use dotnet format before your final commit to clean up spacing and style automatically
  • Re-read the requirements checklist before submitting — make sure all 8 concepts are clearly present
